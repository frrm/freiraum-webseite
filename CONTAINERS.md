# OCI image

`make image` builds a local runtime image; `make oci` exports the multi-platform OCI archive to `dist/freiraum.oci.tar` with provenance and SBOM attestations. It creates or reuses the dedicated `freiraum-website-oci` Docker-container builder without changing the selected builder; set `BUILDER` to use another Docker-container builder. `make push TAG=<tag>` explicitly publishes the archive after separate Trivy scans of both architectures and requires Docker Buildx and registry authentication. Trivy and Skopeo run in pinned containers, so they do not need to be installed on the host. Provide a registry token via standard input, for example `printf '%s' "$TOKEN" | REGISTRY_USER=<username> make push TAG=<tag>`; the temporary registry credentials exist only in the publishing container. The pinned base is upgraded from Alpine security repositories during the image build; this means rebuilds can produce different package versions. CI publishes a unique run tag on trusted master, release tags, nightly and manual runs; release tags also receive their version; successful master builds update `latest`. Pull requests build and scan but cannot publish. A fixable high or critical vulnerability blocks publication.

Run the image with a read-only root and a writable `/tmp`, for example `docker run --read-only --tmpfs /tmp -p 8080:8080 ghcr.io/frrm/freiraum-webseite:<tag>`. `/healthz` provides a health check. The OCI revision label records the source commit; scheduled builds can differ because the calendar is refreshed.
