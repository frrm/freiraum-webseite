Writing software is difficult. (Automatic, static) software verification is a tool that periodically surfaces for a short time and then disappears again. Its goal is to use an algorithm to determine whether a program works “correctly.”

This talk mainly aims to explain why verification has not really caught on, what “correct” is supposed to mean, what else verification can be used for, and ultimately what we can learn from it without having to apply it.
