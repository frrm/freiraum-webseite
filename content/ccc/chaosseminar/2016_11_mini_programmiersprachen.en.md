Perhaps this sounds familiar: you first write a little program that does something useful. Then you extend it because it works so well; next, you want it to be interactive, so you somehow build an input-switch-case loop. Before you know it, you have accidentally created a primitive programming language.

At that point, it would be great not to have to type a command repeatedly, but to have a "do this N times" construct. Eventually the language becomes Turing-complete.

The speaker has built these kinds of micro-programming languages several times. If others bring an example, it could make for an interesting patchwork talk.

This talk introduces a calendar that can launch code and, conveniently, handles data interfaces and data transfer between jobs. More or less by accident, this grew into a distributed programming system. Because it was not planned but evolved over time, it has some properties that conventional distributed programming languages (or parallelization extensions, ...) do not. Whether they are useful is open for discussion. :-)
